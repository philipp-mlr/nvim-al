# nvim-al v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Neovim plugin that gives Business Central AL projects VS Code-equivalent language features, workspace handling, builds and debugging, using the EditorServices binary from the AL VS Code extension.

**Architecture:** Pure Lua package `lua/nvim-al/`. Pure modules (jsonc, workspace, closure, settings, launch, quickfix parsers) are unit-tested headless. Process-facing modules (lsp, build, dap, altool) wrap `vim.lsp`, `vim.system` and nvim-dap and follow `docs/protocol.md` exactly. One language server client per resolved workspace.

**Tech Stack:** Lua (LuaJIT), Neovim ≥ 0.11 APIs (`vim.lsp.start`, `vim.system`, `vim.fs`, `vim.uv`), mini.test for tests, nvim-dap (optional), stylua, .NET 10 for the AL binaries.

**Spec:** `docs/specs/2026-11-03-nvim-al-design.md`, protocol reference `docs/protocol.md`. Read both before starting any task.

## Global Constraints

- Neovim ≥ 0.11; no plugin dependency except nvim-dap, and only in `lua/nvim-al/dap.lua`.
- AL extension ≥ 30.0, dotnet layout only (`extension/bin/Microsoft.Dynamics.Nav.EditorServices.Host.dll`); refuse older with a clear message.
- Every binary path comes from `toolchain` (the single resolver). No other module builds a path into the extension.
- Credentials: never written to disk, never sent to the language server; passed to child processes only as `BC_SERVER_USERNAME` / `BC_SERVER_PASSWORD`.
- v1 authentication: `UserPassword` and `Windows`. Any other value → error `nvim-al: authentication '<x>' is not supported in v1 (UserPassword, Windows)`.
- Workspace discovery stops at the git root (a `.git` file or directory). Several matching workspace files → outermost wins; ties at the same depth → alphabetical plus a one-time notice.
- Settings are passed to the server unresolved, except `${analyzerFolder}` when `setup({ analyzer_folder })` is set.
- `assemblyProbingPaths` is always an array, never nil.
- Paths compared case-insensitively on Windows only; always normalised with `vim.fs.normalize`.
- No Microsoft code or binaries in the repository. MIT licence.
- Formatting: stylua (column width 100, 2-space indent). Commit messages: Conventional Commits.

## Review Focus

1. **Files outside any AL project** (a `.al` file with no `app.json` up to the git root, or outside a git repo): nothing starts, no error spam. The single notify `nvim-al: no app.json found for <file>` appears once per file. Test in Task 3 (resolve returns nil) and Task 6 (attach notifies once, starts no client).
2. **`app.json` with a UTF-8 BOM or trailing commas** (common in BC repos): parsed fine. Test in Task 2 and Task 3.
3. **Rapid buffer switching between projects** (`:bnext` held down): at most one `al/setActiveWorkspace` in flight; the last folder wins. Test in Task 6.
4. **Language server crash or missing .NET runtime**: a clear one-line error naming the cause (`dotnet` not found / needs Microsoft.AspNetCore.App 10.0 / host exited with code N) and no restart loop. Test in Task 5 and Task 6.
5. **Two git worktrees of the same repo open in one Neovim**: two separate clients, each scoped to its own worktree; diagnostics never cross. Test in Task 3 (keying) and Task 6 (client per workspace key).

Data shapes shared across tasks (Lua tables, documented with LuaCATS annotations in the module that owns them):

```lua
---@class nvim_al.Manifest   -- from app.json
---@field id string  name string  publisher string  version string
---@field dependencies {id:string, name:string, publisher:string, version:string}[]
---@field raw string          -- file text without BOM

---@class nvim_al.Folder
---@field path string         -- absolute, normalised
---@field name string         -- workspace folder "name" or basename
---@field index integer       -- 0-based position in the workspace
---@field manifest nvim_al.Manifest|nil

---@class nvim_al.Workspace
---@field key string          -- workspace file path, or folder path in single-folder mode
---@field file string|nil     -- .code-workspace path
---@field root string         -- git root
---@field folders nvim_al.Folder[]
---@field settings table      -- workspace file "settings" (raw al.* keys), {} if none
---@field launch table|nil    -- workspace file "launch" section

---@class nvim_al.Target       -- a resolved launch configuration
---@field name string  request "launch"|"attach"|"snapshotInitialize"
---@field server string  port integer  serverInstance string  tenant string|nil
---@field authentication "UserPassword"|"Windows"
---@field environmentType string|nil  environmentName string|nil
---@field raw table           -- the full resolved configuration sent to the adapter
```
